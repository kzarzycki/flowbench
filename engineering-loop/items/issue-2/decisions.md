# decisions.md — flowbench issue #2 (S01.3)

Self-answered; each is an inference from E01 + the two runners' code, not a product call unless marked.

1. **How does a build-shaped case fit a planning-shaped `run_case`?** Two knobs, no new orchestrator: `done_token` and an optional per-flow `score_flow` hook; the comparative judge becomes conditional on `judge.md` existing. Rejected: keeping the parked branch's second orchestrator (`feat/todo-app-run-case`, July) — it is what E01 exists to remove; rejected: a `case.yaml` — schema is E03.
2. **Artifact name / `git_init` are case properties, not flow properties.** → keywords on `omni_factories`/`make_flow_driver_omni`, defaults = today's swe_planning values.
3. **Superpowers skills: vendor, do not glob the host plugin cache.** #60's lesson (a flow that names a host plugin is hidden configuration) and the flow-is-the-full-configuration record. 6.3.0 is what the cache holds today; all 14 skill dirs because the build workflow spans brainstorm→plan→implement→review (swe_planning vendors only the 3 it needs). `VERSION.md` records the version; the old paths carried it in the manifest, the vendored ones do not — acceptable until E03 records the bundle in run.json.
4. **Where does todo_app scoring live?** `cases/todo_app/scoring.py`, scenario-side, `score_flow` contract `(flow, flow_dir, session) -> dict`. The grader is injected (`make_grader`) so the whole scorer runs offline with a canned model; the real one is a `SessionModel` over omnigent like the engine's judge.
5. **Outputs per flow.** `run_case` writes `plan.md`/`transcript.md`/`session.json` (unchanged; `plan.md` holds the artifact text, here `tasks.json`'s content — harmless); `score_flow` adds `acceptance.json` + `scorecard.json`. Dropped: `run.md`, `transcript.json`, `judge.json`, `clarifying.json` (nothing reads them; `compare` reads `scorecard.json` only).
6. **`resolve_invoker` console-script bug (E01 lists it under S01.3).** Split into flowbench #46: unrelated to the port, needs its own fixture app; keeps this diff reviewable. The PR amends the epic line so the story text and the ACs agree.
12. **A scorer failure is a FAILED column, not an aborted run.** `SessionModel.generate` raises on a non-idle grader turn and `judge_build` does not catch; left alone, one throttled grader would kill the remaining flows, contradicting `compare`'s "never aborts on one bad flow". `run_case` owns that guard (one place, all scorers), not each scenario's `score_flow`.
13. **No `report.html` without a judge.** `render_report` is the comparative-judge report (reads `judge.md`, `winner`); todo_app's read-out is `flowbench compare`. Teaching `render_report` a no-judge layout is report work with no consumer today.
7. **S01.4 in the same PR?** No. PR 2 of this issue, pure deletion, sonnet-implementable once PR 1 removes the last `inspect_ai` import.
8. **`flow_stats.plan_lines` name.** Keep; renaming touches the report and every test; E03 owns metadata schema.
9. **Models.** Engine constants `SIM_MODEL = JUDGE_MODEL = "opus"` stay (one execution model). Flows: `model: sonnet` for both — todo_app's Inspect-era runs were `claudesub/sonnet`, and S01.5 compares against them. Product call deferred: opus-tier flows are issue #27.
10. **Default runs root.** `../flowbench-runs/coding_workflow/<run_id>/` (engine convention `<runs_root>/<run_id>/<flow>/`); the Inspect-era `todo-app-eval/` stays as history. `compare --run-base` points at whichever.
11. **`run_dir.py` goes.** Its three functions served the Inspect solver only (prepare workspace + copy `case/` + `write_outputs`/`run.md`). `run_case` makes the dirs; decision 5 covers outputs.
