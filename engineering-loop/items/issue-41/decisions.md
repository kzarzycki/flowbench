Self-answered questions; each is an inference from the issue + E01 + code, not a product call.

1. **Where does `default_runs_root()` go?** It anchors off the scenarios repo (`_REPO_ROOT.parent/flowbench-runs/swe_planning`); the engine has no such anchor. → Engine `run_case`/`run_case_n`/`RunWatch` take `runs_root` as a REQUIRED keyword (no `None` default). `default_runs_root()` stays scenario-side (S01.2 keeps it and passes it in). Tests for it stay scenario-side.
2. **The `swe_planning/` prefix in `_project()` and `RunWatch.project`.** Hardcoded scenario name; today independent of `--runs-root`. → Explicit label, no derivation: `run_case`/`run_case_n` take `scenario: str` (required keyword, written to run.json as `"scenario"`); the omni factories take it via `omni_factories(scenario) -> (make_flow_driver, make_simulator, run_judge)` (partials over `make_flow_driver_omni(flow, flow_dir, *, scenario)` etc., so the 2-arg factory contract run_case calls is unchanged); `RunWatch(run_id, *, runs_root, scenario)`. Scenarios pass `"swe_planning"` → byte-identical titles/projects. (Gate-1 objection 4: derivation from `runs_root.name` would change grouping under a custom `--runs-root`.)
3. **`DONE_TOKEN`, `MISSING_PLAN`, `SIM_MODEL`, `JUDGE_MODEL`, `artifact_name="plan.md"`.** Case-shaped constants baked into `run.py`. → Move as module constants of `flowbench/run.py`, unchanged. Parameterizing is S01.3/E03 (E01: "do not redesign while moving").
4. **`main()` / `_parse_args` / `_positive_int` (run.py) and `main()` (watch.py).** Scenario entrypoints; depend on `default_runs_root`/`scenario.py`. → Both stay scenario-side (S01.2 rewires them to the engine classes). `flowbench run`/`flowbench watch` is S03.x. Their tests stay scenario-side.
5. **`[swe_planning]` stderr prefix in `OmnigentModel.generate`.** → `[flowbench]`. Only the prefix changes. `GENERATE_ATTEMPTS`/`GENERATE_RETRY_WAIT_S` live in `model.py` (the reader of the constants; run.py imports model.py, so the reverse would be a cycle).
6. **"scenario swe_planning" label in `report.py` HTML.** → `meta.get("scenario", "")` from run.json (written by run_case per decision 2; aggregate run.json gets it too). Hand-built run.json in report tests without the key renders an empty label.
7. **`_item_text` is private and imported by scenarios (issue #3).** → `flowbench/transcript.py` exports `item_text`, `last_assistant_text`, `n_assistant_messages`, `is_control_message`, `dedup_items`, `render_transcript`. `driver.py` imports them from there (transcript.py is pure, no cycle) and keeps `_item_text = item_text` as a one-line alias until S01.2 deletes the scenarios import.
8. **`pyyaml` is not an engine dependency** (`helpers.load_flows` needs it). → Add `pyyaml>=6` to core `dependencies` (stdlib has no YAML; it is already in the env transitively).
9. **`last_json_object` brace counting.** E01 asks for a string-aware fix while moving. → Scan with a tiny state machine (in-string / escape) instead of raw `}`/`{` counting; add the regression test (`{"a": "}"}`-shaped input).
10. **Which tests port?** All 25 of `test_swe_planning_helpers.py` and 33 of the 37 in `test_swe_planning_run.py`; the 4 that stay scenario-side are `test_default_runs_root_is_sibling_of_repo` and the 3 `test_parse_args_*`.
